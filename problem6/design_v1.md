### 2.2 The function (R5 to R11)

```python
def euler_totient(n: int) -> int:
    """Return phi(n), the count of integers in 1..n-1 coprime to n (phi(1) = 1).

    Args:
        n: A positive integer (bool is rejected).
    Returns:
        The number of integers i with 1 <= i < n and gcd(i, n) == 1;
        1 when n == 1.
    Raises:
        TypeError: If n is not an int (including bool, float, str, None, ...).
        ValueError: If n < 1.
    """
    if not isinstance(n, int) or isinstance(n, bool):
        raise TypeError(f"euler_totient() argument must be int, got {type(n).__name__}")
    if n < 1:
        raise ValueError(f"euler_totient() argument must be a positive integer, got {n}")
    if n == 1:
        return 1
    count = 0
    for i in range(1, n):
        if gcd(i, n) == 1:
            count += 1
    return count
```

Design points:

- Steps follow R7a to R7f in the exact order. The `bool` test is part of step a (R6a).
- `isinstance(n, int)` already rejects `float` (including `5.0`), `str`, `None`, `Decimal` and `Fraction`. There is no conversion anywhere.
- `n == 1` is a separate early return because the loop `range(1, 1)` would be empty and give 0, not the conventional 1 (Overview).
- `range(1, n)` is the 1..n-1 inclusive loop (R7e). The loop is iterative; there is no recursion (R10).
- Every coprimality test calls the imported `gcd`. No `math.gcd`, no factorization (R8).
- Correctness for arbitrary positive `int` follows from Python's unbounded integers; there is no size cap or timeout (R11).
- Complexity is about n-1 gcd calls of O(log n) each, so O(n log n) (R17). Mentioned in the README, with a one-line note in the docstring only if it stays concise.

## 3. `__main__` test block (R13 to R15)

### 3.1 Structure

A small local helper keeps the counters and output format in one place:

```python
def report(label, expected_text, ok):
    # prints "<label> (expected <expected_text>) PASS|FAIL"; updates total/passed
```

Each test calls `report`. At the end:

```python
print(f"{passed}/{total} passed")
sys.exit(0 if passed == total else 1)
```

Output format (R13):

```
euler_totient(12) = 4 (expected 4) PASS
euler_totient(0) raises ValueError (expected ValueError) PASS
...
34/34 passed
```

A test that raises an unexpected exception is caught and reported as `FAIL` (so one bad case does not abort the run), which is more robust than Problem 5's approach. Exit status is nonzero if any test fails (R13).

Notes:

- The `euler_totient(12)` case appears once, in the value tests (R14).
- Expected values are written as literals taken from known totient values and checked by hand; the multiplicativity and prime-power checks use formulas whose inputs are the small hand-verified cases from R14d and R14e. `math.gcd` is used only in the test section (R8, R14f).
- The cross-check test is a single reported line to keep the output readable. It is an addition beyond the 33 explicitly listed checks; R14f allows but does not require it. **Open point for approval:** keep it (34 tests) or drop it (33 tests).
- TypeError tests catch only `TypeError` as a pass; a `ValueError` or no exception is a `FAIL`. ValueError tests behave likewise. Only the exception type is checked, not the message (R6c).
- `Decimal`/`Fraction` are imported inside the `__main__` block.
- The value test for the n = 100 case plus all the others is expected to run in well under two seconds (R15). Timing is not asserted in the script.

## 6. Verification plan (after implementation)

1. Run from the repository root: all tests pass, exit code 0.
2. Run from inside `problem6/` and from another directory: same result (R4).
3. `python -c "import euler_totient"` from `problem6/` prints nothing (R16).
4. Temporarily break the function, for example by changing `== 1` to `== 2` in the `gcd` test, and confirm a `FAIL` line, a failed summary and a nonzero exit code. Revert afterwards.
5. Confirm `git status` shows no changes under `problem5/` (R4).
6. Grep the function body to confirm no `math`, no recursion and no inline gcd (R8, R10).
7. Regenerate `Results/totient_output.txt` with the documented commands and check it against the README.
8. Record the actual Python version in the README.
