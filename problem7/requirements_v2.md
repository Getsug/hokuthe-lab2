
### Overview
This is a Python program that verifies the relationship between Euler's totient function and the product of two distinct primes. The program selects distinct primes $p$ and $q$ between $2000$ and $3000$ (inclusive), validated with the `is_prime()` function from Problem 2, and calculates $n=pq$. It computes $\phi(n)$ with the `euler_totient()` function from Problem 6 (which relies on the non-recursive GCD function from Problem 5) and compares the result with the theoretical formula $\phi(pq)=(p-1)(q-1)$. The comparison is repeated for five distinct unordered prime pairs, plus one equal-prime contrast case. The program reuses the existing functions without modifying, copying or reimplementing them. It displays the selected primes, their product, the computed totient, the theoretical value, whether they match, and per-pair and total execution times. Results are saved in the `Results` folder.

### Project Requirements
1. The project is housed in a folder called **problem7**. All new files live inside `problem7/`; nothing may be modified, copied or added inside `problem2/`, `problem5/` or `problem6/`.
2. Python 3.14.7 is the intended development version. It is not enforced at runtime. The README documents the version actually used for testing.
3. Use only the standard library plus the imported `euler_totient` and `is_prime`. Do not use recursion.
4. **Imports:** `euler_totient` from `problem6/euler_totient.py` and `is_prime` from `problem2/primality.py` are reused unchanged. Their directories are resolved relative to `__file__` (e.g. `Path(__file__).resolve().parent.parent / "problemN"`), so the program works from any current working directory.
5. **Deliverables** (all in `problem7/`):
    - `verify_totient.py`: contains `verify_totient_identity(pairs)` and `main()`, with an `if __name__ == "__main__":` block that calls `main()`.
    - `test_verify_totient.py`: `unittest` tests (see requirement 14).
    - `README.md` (see requirement 15).
    - `Results/totient_verification.txt`: generated by the program.
6. **Primary function** `verify_totient_identity(pairs)` takes a list of prime pairs `[(p, q), ...]` and returns a list of result dictionaries, one per pair, with exactly the keys `p`, `q`, `pq`, `phi_pq`, `expected` (`(p-1)*(q-1)`) and `matches` (bool). No dataclasses or custom record classes.
7. **Input validation** (all done before any mathematical computation, for the whole batch, with clear error messages):
    a. `pairs` must be a list, otherwise `TypeError`.
    b. Each element must be a tuple, otherwise `TypeError`. A tuple whose length is not 2 raises `ValueError`.
    c. Each of `p` and `q` must be an `int`. Booleans and other non-integers raise `TypeError`. This check is explicit even though `is_prime()` also rejects unsupported types.
    d. Each of `p` and `q` must be in the inclusive range 2000 to 3000, otherwise `ValueError`.
    e. Each of `p` and `q` must be prime according to the imported `is_prime()`, otherwise `ValueError`. Invalid candidates are never silently skipped.
    f. `p != q`, otherwise `ValueError("p and q must be distinct primes")`.
    g. `(p, q)` and `(q, p)` are the same combination. A batch containing a duplicate combination raises `ValueError`.
    h. Validation fails fast on the first invalid pair. No partial results are returned.
8. **Computation**, for each validated pair, in order: `n = p * q`; `phi_pq = euler_totient(n)` using the Problem 6 function; `expected = (p - 1) * (q - 1)`; `matches = (phi_pq == expected)`; append the record. Return the list. An empty list returns `[]`. The theoretical formula must never replace the `euler_totient` computation.
9. **Primary pair:** `(2003, 2011)`, fixed and reproducible. It is displayed at the top of both stdout and `Results/totient_verification.txt`.
10. **Additional pairs:** exactly four, giving five distinct unordered pairs in total. Each was confirmed prime and in range with `is_prime()`:
    - (2017, 2027)
    - (2029, 2039)
    - (2081, 2083)
    - (2969, 2999)

    Primality is validated inside `verify_totient_identity()` only, not repeated in `main()`.
11. **Contrast case:** `(2011, 2011)` is passed to `verify_totient_identity` separately from the five-pair batch. `main()` catches only the expected equal-prime `ValueError` (identified by its "distinct primes" message). Any other validation error is a real failure, not a successful contrast. `main()` then prints and writes a clearly labeled note that `(2011, 2011)` is rejected because the primes are not distinct, and that $\phi(p^2)=p(p-1)$ rather than $(p-1)^2$. The contrast case is not part of the results table and does not affect the PASS/FAIL summary.
12. **Results file** `Results/totient_verification.txt`:
    - The path is resolved relative to the script. `Results/` is created automatically if missing, and the file is overwritten on each run.
    - Structure, in order: primary pair at the top; table with one row per pair and columns `p`, `q`, `pq`, `phi(pq)`, `(p-1)(q-1)`, `match?`; per-pair times and total runtime; contrast-case note; conclusion; final summary line.
    - The conclusion is a short mathematical explanation: for distinct primes, $\phi(p)=p-1$ and $\phi(q)=q-1$, and $\phi$ is multiplicative on coprime arguments, so $\phi(pq)=(p-1)(q-1)$.
    - The file ends with `All distinct-prime cases verified: PASS`, or `FAIL` if any comparison does not match.
    - The same content is printed to stdout.
13. **Timing and exit status:**
    - Measure each pair's `euler_totient` time and the total runtime with `time.perf_counter()`. Report both in stdout and the results file. There is no hard time limit.
    - Exit with a nonzero status if any identity comparison fails, or if the experiment cannot complete (e.g. an unexpected exception or a file-write failure). Otherwise exit with 0.
14. **Tests:** `test_verify_totient.py` uses the standard-library `unittest` framework and covers the following.
    - Valid pairs, with fast checks. Expensive full-range verification is kept out of the unit tests, which avoids repeated heavy computation.
    - Equal-prime rejection (`ValueError`).
    - Composite and out-of-range rejection (`ValueError`).
    - Non-integer and boolean inputs (`TypeError`).
    - Malformed inputs: non-list `pairs`, non-tuple element (`TypeError`), wrong-length tuple (`ValueError`).
    - Duplicate and reversed combinations (`ValueError`).
    - An empty list returns `[]`.
    - Output consistency: the results file contains the expected valid-pair records, and its summary reflects the actual comparisons.
15. **README** covers: the problem objective, mathematical explanation, algorithm, dependencies on Problems 2, 5 and 6, execution commands, testing instructions, output files, actual measured runtimes, the Python version used for testing, and known limitations (e.g. the O(n) GCD-based totient is slow for $n$ of several million).
